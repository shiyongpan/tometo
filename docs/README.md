## 編號規則

| 前綴 | 用途 | 格式 | 範例 |
|---|---|---|---|
| `STK` | 利害關係人需求 | `STK-nnn` | STK-001 |
| `SYS` | 系統功能需求 | `SYS-nnn` | SYS-012 |
| `QS` | 品質需求，以品質情境表達；每條寫出「來源 STK」，「對應 SYS」是它約束的功能需求，可以空白 | `QS-nnn` | QS-003 |
| `CON` | 限制條件 | `CON-nnn` | CON-002 |
| `ASM` | 假設與相依 | `ASM-nnn` | ASM-001 |
| `IF` | 外部介面 | `IF-nnn` | IF-001 |
| `ADR` | 架構決策 | `ADR-nnnn` | ADR-0001 |

- 編號依十位數分組，組內可以跳號，留給之後新增：
  - STK：001～ 玩家、010～ 主機管理者、020～ 開發者、030～ 公司（STK-030 主管已廢止）
  - SYS：001～ 在線掛機與離線結算、010～ 存檔、020～ 上班模式、030～ 省資源、040～ 設定、100～ 設施、110～ 角色與裝備、120～ 冒險、130～ 主動挑戰與區域、140～ 目標成就、150～ 轉生、160～ 短任務、170～ 新手引導、200～ 多人
  - QS：001～ 易用性、010～ 可復原性、020～ 可維護性、030～ 效能、040～ 擴展性、050～ 可用性、060～ 安全
- 能力代碼：`C01`～`C10` 是平台能力（C07～C09 保留）、`G01`～`G08` 是遊戲玩法能力，定義在 `01` 第 4 章；一個能力對應 1～5 條 SYS（C03 存檔 10 條、C04 上班模式 7 條是例外）。
- 不適用的驗證方法寫「N/A（原因）」，不寫「—」。
- 編號一旦發出就不重用；廢止的項目保留編號，狀態改成「廢止」並寫原因。
- 需求追溯方向：STK → SYS → QS／架構元件／ADR → 驗證方法（測試、檢視、展示、分析）。

## 標記

| 標記 | 意思 |
|---|---|
| `【假設】` | Claude 推論、尚未經使用者確認 |
| `<待確認：...>` | 還不知道的事實，同時列在 `spec-progress.md` 的待確認問題 |

## 優先序

Must（沒有就不算這個系統）／Should（重要但可延後）／Could（有更好）。
