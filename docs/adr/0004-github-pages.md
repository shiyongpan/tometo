# ADR-0004：發佈在 GitHub Pages，repo 公開

- 狀態：已接受
- 日期：2026-11-20
- 決策者：使用者（開發者）
- 對應需求：IF-001；CON-003、004、006、007；ASM-002；QS-050、062；`02` R5、R8、R9

## 背景
第一版沒有遊戲主機，遊戲是一個靜態網頁。同事要能用公司電腦的瀏覽器打開，更新時大家要拿到新版。v0.1 開工前要決定發佈位置，因為它會影響 repo 是否公開，以及 localStorage 的來源（網址一變，存檔就要用匯出匯入搬家）。沒有期限。

決策驅動因素（提議的順序，使用者在選定方案時同意）：
1. 公司網路連得到（ASM-002）
2. 不用自己開主機或維運（CON-007）
3. 不洩漏公司資訊、曝光可控（QS-062、R8）
4. 更新方便

## 考慮過的選項
1. **A：GitHub Pages＋GitHub Actions**：push 後先跑測試，再只複製遊戲檔發佈；免費方案的 repo 必須公開。
2. **B：單一 HTML 檔**：把模組串成一個檔案，用通訊軟體傳。
3. **C：公司內網主機**（北境求生做法）：在某台電腦用 Node 提供網頁。
4. **D：其他靜態託管**（Cloudflare Pages、Netlify 等）：連結 GitHub repo 自動發佈，repo 可以是私有的。

| 驅動因素 | A | B | C | D |
|---|---|---|---|---|
| 1 公司連得到 | ✅ 使用者已確認 | ✅ | ✅ | `<待確認>` 公司是否擋這些網域 |
| 2 免維運 | ✅ | ✅ | ❌ 要有人一直開著主機 | ✅ |
| 3 曝光 | ⚠️ repo 公開、網址任何人可開 | ✅ 完全不公開 | ✅ | ⚠️ 程式碼可私有，網址仍任何人可開 |
| 4 更新方便 | ✅ push 就發佈 | ❌ 每版重傳、同事版本不一 | ⚠️ | ✅ |

切換代價：
- A、B、D 都是靜態檔案，互相切換只要換部署設定；網址改變時，玩家要用匯出匯入搬存檔。
- C 要多寫並長期維運一支伺服器。

## 決策
採用 A：GitHub Pages＋GitHub Actions。範圍從「不對外公開」改成「不宣傳但可公開」。

## 理由
- 第 1、2 名都符合：使用者已確認公司能開 github.io，也不用維運主機。
- 第 3 名的代價（repo 公開）可以接受：符合「做作品」的目的，並以 CON-006 管住公司資訊。
- D 是最接近的替代方案；日後想把 repo 改成私有，換過去成本很低。

## 後果
- 好處：零成本、零維運，push 就更新。
- 代價：網址任何人都能開（R8）；repo、網站、commit 紀錄都不能有公司資訊（CON-006）；網址會出現在網址列與歷史紀錄（R5）。
- 之後要注意：
  - Actions 先跑 `node --test`，通過才複製遊戲檔（`index.html`、`css/`、`src/`、素材）發佈；只複製、不建置。
  - commit 作者用使用者的個人 email（使用者指定，設在 repo 的 `.git/config`），不用公司 email。
  - 同一帳號的所有 Pages 共用 localStorage 來源，鍵名要加前綴（ADR-0005）。
  - repo：`shiyongpan/tometo`，網址 `https://shiyongpan.github.io/tometo/`。
  - 模組放在版本目錄，避免快取混用新舊模組（R9）。

## 重新檢視的條件
- 公司開始擋 github.io（在公司電腦打不開）：改用 B（單一 HTML 檔，ASM-002 備案）或 D。
- 想把 repo 改成私有：改用 D（先確認公司沒擋該網域）。
- 發現有不在目標範圍的人大量來玩，或網址被公開轉傳：重新評估曝光（例如改用 B）。
- 開始做多人版、需要主機時：重新評估整體部署。
