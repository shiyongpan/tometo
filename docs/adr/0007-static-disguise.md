# ADR-0007：偽裝畫面用靜態樣板試算表

- 狀態：已接受
- 日期：2026-11-20
- 決策者：使用者（開發者）
- 對應需求：SYS-020、021、025、026；QS-001、002、007、061；CON-003、006、007

## 背景
按下隱藏鍵後，畫面要在 1 秒內變成像真的試算表（QS-001、002）。v0.1 就要有上班模式，所以開工前要決定偽裝畫面的做法；它會影響 HTML 結構（偽裝根元素要在 HTML 裡就存在，才能讓重新整理時直接顯示偽裝，QS-007）。沒有期限。

決策驅動因素（提議的順序，使用者在選定方案時同意）：
1. 1 秒內生效（QS-001）
2. 看起來像真的（QS-002）
3. 零網路請求（QS-061、CON-003）
4. 維護成本（QS-020、CON-007）
5. 偽裝時還能看到進度（加分項）

## 考慮過的選項
1. **A：靜態樣板試算表**：一份固定的虛構試算表，跟遊戲內容無關；切換只是顯示與隱藏兩個根元素。
2. **B：動態偽裝**：把遊戲數字排成表格。
3. **C：整個遊戲做成試算表風格**（有些「試算表放置遊戲」是這樣做）：不用切換。
4. **D：傳統「老闆鍵」**：導向真的網站或另一個分頁，例如真的 Google 試算表。

| 驅動因素 | A | B | C | D |
|---|---|---|---|---|
| 1 1 秒 | ✅ | ✅ | ✅ 不用切換 | ✅ |
| 2 像真的 | ✅ | ⚠️ 數字一直跳動，不像試算表 | ⚠️ 遊戲畫面還是會變動 | ✅ 本來就是真的 |
| 3 零請求 | ✅ data URL | ✅ | ✅ | ❌ 違反 CON-003 |
| 4 維護 | ✅ 幾乎不用維護 | ❌ 遊戲內容一改就要跟著改 | ⚠️ 美術受限 | ✅ |
| 5 看進度 | ❌ | ✅ | ✅ | ❌ 遊戲分頁可能被凍結 |

切換代價：
- A → B：在樣板裡放一兩個數字，難度低。
- C：等於重做整套美術。
- D：違反限制條件。

## 決策
採用 A：靜態樣板試算表，連分頁標題與圖示一起換。

## 理由
- 前四名驅動因素都符合；代價只有第 5 名（加分項）的「偽裝時看不到進度」。
- 不跟著遊戲內容變，就不會增加維護量（`01` 5.3 的易用性與可維護性取捨）。
- D 違反 CON-003。

## 後果
- 好處：簡單、可靠，幾乎不用維護。
- 代價：偽裝時看不到遊戲進度；網址列與歷史紀錄仍會顯示網址（`02` R5）。
- 之後要注意：
  - 樣式跟真的試算表一樣是灰白色系，沒有動畫與鮮豔色塊（QS-002）。
  - 假資料用虛構內容，不含公司資訊（CON-006）。
  - 偽裝的分頁圖示與素材用 data URL 內嵌，切換時不發網路請求（CON-003）。
  - 偽裝根元素寫在 HTML 裡，偽裝狀態存在 localStorage；重新整理時依狀態直接顯示偽裝，並可設定「開啟時預設偽裝」（SYS-025、026）。
  - repo 名稱是 `tometo`，網址列會顯示 `shiyongpan.github.io/tometo`（`02` R5）。

## 重新檢視的條件
- 自己或同事在 4 週內有 2 次以上因為「想看進度」而在上班時切回遊戲畫面：考慮在樣板裡放一兩個不顯眼的數字（往 B 靠）。
- 有人從 2 公尺外認出偽裝畫面不是真的試算表（QS-002 失敗）：改版樣板，參考當時公司實際使用的試算表版面。
- 隱藏鍵切換在參考電腦上超過 1 秒（QS-001 失敗）：檢查是不是切換時觸發了重畫或載入。
