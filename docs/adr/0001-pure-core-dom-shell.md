# ADR-0001：純函式核心＋原生 DOM 外殼

- 狀態：已接受
- 日期：2026-11-20
- 決策者：使用者（開發者）
- 對應需求：SYS-001～003、007、030；QS-001、020、021、030、040；CON-001、007；STK-020

## 背景
v0.1 開工前要先定程式的整體結構。不定的話，第一批程式會照北境求生的習慣寫成 canvas 加全域可變狀態，之後模擬工具（QS-021）與多人版（QS-040）都得重寫。

放置遊戲要在背景掛一整天而且幾乎不吃 CPU（QS-030）；在線與離線的結算要能用同一套公式、分段計算結果一致（SYS-007）。北境求生的做法是 canvas 每幀重畫，已在規格階段排除。沒有期限，寫第一行程式之前決定即可。

決策驅動因素（使用者排定的順序）：
1. 掛機 CPU 低於 1%（QS-030）
2. 在線與離線分段計算結果一致（SYS-007）
3. 遊戲規則能直接在 Node 執行：模擬工具與多人版（QS-021、040）
4. 隱藏鍵 1 秒內生效（QS-001）
5. 新增內容只改資料表（QS-020）
6. 熟悉度（STK-020）

## 考慮過的選項
1. **A：純函式核心＋原生 DOM 外殼**：`core/` 只做「狀態＋經過時間 → 新狀態」，不碰 DOM、時鐘、儲存；`shell/` 處理副作用；畫面只在可見而且有變動時更新。
2. **B：北境求生做法**：canvas 每幀重畫、classic script、全域狀態。規格階段已排除（違反 QS-030、SYS-007）。
3. **C：A＋Web Worker**：`core` 在 Worker 執行。
4. **D：可變狀態物件＋DOM**：傳統放置遊戲的寫法（例如 Cookie Clicker），全域 `Game` 物件由 `setInterval` 直接修改。
5. **E：純函式核心＋UI 框架**：前端業界主流（Preact、Lit 等），狀態變了由框架重畫。
6. **F：遊戲引擎**：遊戲業界主流（Phaser、Godot Web 匯出等）。

| 驅動因素 | A | D | E | F |
|---|---|---|---|---|
| 1 CPU（QS-030） | ✅ 背景不重畫 | ✅ | ⚠️ 要注意框架重畫 | ❌ 每幀渲染 |
| 2 一致性（SYS-007） | ✅ 純函式好測 | ❌ 受執行順序影響 | ✅ | ❌ |
| 3 Node 模擬與多人（QS-021、040） | ✅ 直接 import | ⚠️ 要先拆掉 DOM | ✅ | ❌ |
| 4 隱藏 1 秒（QS-001） | ✅ | ✅ | ✅ | ⚠️ 要另外疊 DOM |
| 5 資料表（QS-020） | ✅ | ⚠️ 容易混進邏輯 | ✅ | ⚠️ |
| 6 熟悉度（STK-020） | ⚠️ 新寫法 | ✅ | ❌ 新框架 | ❌ |
| 限制 CON-001 | ✅ | ✅ | ❌ 違反 | ❌ 違反 |

切換代價：
- A：要從北境求生的習慣轉換寫法；日後改成 D 很容易，反過來很難。
- D：學習成本零；日後改成 A 等於重寫整個核心。
- E：要學框架、把框架程式碼放進 repo；日後換或拿掉框架只影響 `shell/render`。
- F：學習成本高、檔案大；日後要反悔最難。
- C：比 A 多一層訊息傳遞；計算量小，用不到「畫面不被卡住」的好處。

## 決策
採用 A：純函式核心＋原生 DOM 外殼。

## 理由
- 前三名驅動因素都符合：背景與偽裝時不重畫（QS-030）；純函式讓分段一致性可以直接測試（SYS-007）；`core` 能直接給 Node 執行（QS-021、040）。
- D 在第 2、3 名失分；E、F 違反 CON-001；C 的好處在這個計算量下用不到（CON-007）。
- 唯一的代價是熟悉度，這是排在最後的驅動因素。

## 後果
- 好處：容易測試；在線、離線、模擬、之後的多人主機共用一套規則。
- 代價：要學「不直接修改狀態」的寫法；DOM 更新要手寫，面板多時比較繁瑣；戰鬥畫面只用數字、進度條與 CSS。
- 之後要注意：`core` 裡不能使用 `Date.now()`、`Math.random()`、`document`、`localStorage`（ADR-0006）；可以在測試或 lint 檢查 `core/` 沒有出現這些名稱。

## 重新檢視的條件
- 在參考電腦上，單次 tick（`advance`＋畫面標記）超過 50 ms：考慮 C（Web Worker）。
- 手寫 DOM 更新的面板超過 15 個，或同一類畫面錯誤（忘記更新某欄位）在一個月內出現 3 次以上：考慮 E（需要先放寬 CON-001）。
- 決定要做即時戰鬥動畫：只在戰鬥區塊加一個 canvas，背景與偽裝時停止，不推翻這份 ADR。
