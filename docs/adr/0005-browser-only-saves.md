# ADR-0005：第一版存檔只放 localStorage＋匯出檔

- 狀態：已接受
- 日期：2026-11-20
- 決策者：使用者（開發者）
- 對應需求：SYS-010～019；IF-002、003；QS-010～015、060；STK-004；CON-003、007；ASM-003

## 背景
第一版是單人、沒有主機，進度又不能不見（STK-004）。v0.1 開工前要決定存檔放在哪裡，因為存檔格式與存放位置一旦有人在用，日後搬家就要做存檔升級與轉移。沒有期限。

決策驅動因素（提議的順序，使用者在選定方案時同意）：
1. 進度不會不見：存檔最多落後 30 秒、清除網站資料後也救得回來（STK-004，QS-010、011）
2. 不顯眼：不跳視窗、不自動下載（QS-012）
3. 不連網（CON-003）
4. 實作量（CON-007）

## 考慮過的選項
1. **A：localStorage＋匯出檔**：同步讀寫、容量約 5 MB；清除網站資料時靠匯出檔還原。
2. **B：IndexedDB＋匯出檔**（較大型網頁遊戲的主流）：非同步、容量大。
3. **C：自動寫入使用者指定的本機檔案**（File System Access API）：玩家選一個檔案，遊戲自動寫進去。
4. **D：雲端存檔**（Firebase、自架主機）。

| 驅動因素 | A | B | C | D |
|---|---|---|---|---|
| 1 不會不見 | ⚠️ 清除網站資料時只救得回最後一次匯出 | ⚠️ 同 A | ✅ 清除網站資料也還在 | ✅ 換電腦也在 |
| 2 不顯眼 | ✅ | ✅ | ⚠️ 每次開啟可能要授權（`<待確認：Chrome 持續授權的條件>`），會跳權限提示 | ✅ |
| 3 不連網 | ✅ | ✅ | ✅ | ❌ 違反 CON-003，第一版也沒有主機 |
| 4 實作量 | ✅ 最簡單 | ⚠️ 非同步 API 較繁瑣；存檔小，用不到大容量 | ⚠️ | ❌ |

切換代價：
- A ↔ B：只差 `shell/storage.js`，難度低。
- C 可以疊在 A 上面，當作選配的自動備份。
- D 留給多人版，存檔改以主機為準。

## 決策
採用 A：localStorage 自動存檔，加上匯出匯入；超過 3 天沒匯出時顯示不顯眼的提醒。

## 理由
- 第 2、3、4 名都符合，而且最簡單。
- 第 1 名的缺口（清除網站資料）用匯出檔與 3 天提醒補（QS-011、012）；自動下載備份雖然更安全，但上班時會被看到，易用性優先。
- C 是 ASM-003 不成立時的備案，不必第一版就做。

## 後果
- 好處：不需要帳號、伺服器與權限提示。
- 代價：玩家不匯出就自負風險（R1）；同一 GitHub 帳號的所有 Pages 共用 localStorage 來源與約 5 MB 容量（R10）。
- 之後要注意：
  - 鍵名一律加遊戲專屬前綴（IF-002）。
  - 先寫暫存鍵、成功後才換正式鍵，並保留上一份成功的存檔當備份鍵（QS-010）。
  - 多分頁：用 Web Locks 選出唯一的主控分頁，只有它計算與存檔（SYS-019）。
  - 版本：v0.1 起的存檔都能升級（SYS-013）；存檔版本比程式新時拒絕讀寫（SYS-016）。
  - 失敗：讀不懂時不覆蓋原始資料、不自動開新遊戲（SYS-017）；寫入失敗時警告並重試（SYS-018）。
  - 匯入：只用 `JSON.parse`＋結構驗證（QS-060）；先確認、先備份目前存檔，不做離線結算（SYS-014、015）。

## 重新檢視的條件
- ASM-003 不再成立（例如公司原則改變）：在公司電腦關掉瀏覽器再打開，存檔不見→ 加上 C 當自動備份，或改用 D。
- 存檔大小超過 1 MB，或寫入失敗（SYS-018）一週內在同一台電腦出現 2 次以上 → 考慮 B。
- 自己或同事因為清除網站資料而遺失進度 2 次以上 → 加上 C，或縮短匯出提醒間隔。
- 開始做多人版 → 存檔改以主機為準（D）。
