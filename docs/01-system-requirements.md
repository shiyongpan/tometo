# tometo 系統需求規格（SyRS）

- 狀態：草稿（已依 spec-reviewer 審查 RV-01～44 修正）
- 最後更新：2026-11-20

## 1. 簡介
### 1.1 目的
一款在瀏覽器裡玩的放置／掛機遊戲，讓自己和同事能在上班零碎時間玩，忙的時候掛著或關掉也會繼續累積進度。玩法是「設施經營」產出資源，加上角色「冒險自動戰鬥」。第一版只做單人；同事之間的合作與交易留到之後的版本。

開發的主要目的是練習技術、做作品，練習重點放在遊戲設計與數值。技術上保留北境求生的「純 JavaScript、無外部相依、不建置、開發工具只用 Node 內建模組」；刻意不沿用它的 canvas 每幀重畫、classic script 與全域可變狀態，理由見 ADR-0001、ADR-0003。

### 1.2 範圍
**範圍內**
- 桌機瀏覽器上的放置遊戲：設施經營、角色冒險自動戰鬥
- 兩種掛機：分頁開著時自動進行（效率較高）；關掉後回來依離開時間結算部分離線收益（`<待確認：Q2 離線折扣比例與上限>`）
- 第一版：單人，放在 GitHub Pages；存檔在玩家自己的瀏覽器，可匯出匯入；網頁載入完成後不發出任何網路請求
- 之後版本：同事之間的合作與交易（需要主機），第一版架構要預留
- 上班情境：畫面低調不顯眼、一鍵隱藏、預設靜音、幾分鐘能玩一輪

**範圍外**
| 不做的事 | 說明 |
|---|---|
| 金流／付費 | 沒有儲值、廣告 |
| 宣傳與經營 | 網址放在 GitHub Pages、不保證別人開不到，但只給同事、不對外宣傳；遊戲裡不放公司資訊 |
| 手機 | 只保證桌機瀏覽器 |
| 即時對戰 PvP | 玩家之間只有合作與交易 |

### 1.3 成功指標
| # | 指標 | 衡量方式 |
|---|---|---|
| M1 | 完成可玩的第一版 | 能從開局走到第一次轉生，並開始第二輪（v1.0） |
| M2 | 自己持續玩 | 自己連續玩超過 4 週（自評） |
| M3 | 同事在玩 | 至少 3 位同事，每人每週至少上線一次（第一版是各自單人玩）；遊戲不回傳資料（QS-061），所以用詢問同事的方式確認 |
| M4 | 上班玩不顯眼 | 一鍵隱藏在 1 秒內生效（QS-001，可測試）；「沒被發現」本身不客觀量測 |

### 1.4 名詞定義
| 名詞 | 定義 |
|---|---|
| tick | 遊戲每秒一次的進度計算 |
| 在線 | 遊戲分頁開著，而且兩次 tick 的間隔不超過 120 秒（背景分頁被瀏覽器降頻到約 1 分鐘一次也算在線） |
| 離線 | 遊戲關掉的期間，以及兩次 tick 間隔超過 120 秒的那一段（例如電腦睡眠、分頁被凍結或移除、瀏覽器當掉） |
| 在線掛機 | 在線、玩家沒有操作時，遊戲自動進行，收益全額 |
| 離線收益 | 離線期間的收益，套用離線折扣與上限 |
| 一鍵隱藏 | 一個按鍵就讓遊戲畫面變成偽裝畫面 |
| 偽裝畫面 | 按下隱藏鍵後顯示的假試算表／文件 |
| 主控分頁 | 同一個瀏覽器同時開了多個遊戲分頁時，唯一負責計算與存檔的那一個 |

## 3. 系統情境
第一版的遊戲是一個靜態網頁，放在 GitHub Pages。玩家用桌機瀏覽器打開網址，遊戲整個在瀏覽器裡跑，沒有遊戲主機。網頁載入完成後不發出任何網路請求，存檔放在瀏覽器的 localStorage，玩家也可以把存檔匯出成檔案、再匯入回來。

| 對象 | 互動 | 方向 |
|---|---|---|
| 玩家 | 用鍵盤與滑鼠操作、看畫面 | 雙向 |
| GitHub Pages（IF-001） | 提供網頁與素材；開發者在這裡發佈新版 | 讀（玩家）／寫（開發者） |
| 瀏覽器儲存空間（IF-002） | 自動存檔、讀檔、多分頁協調 | 讀寫 |
| 存檔檔案（IF-003） | 匯出備份、匯入還原 | 讀寫 |
| 電腦時鐘 | 計算經過時間 | 讀 |

第一版範圍外：遊戲主機、同事之間的連線（多人版才加，見 STK-003）。

## 4. 功能需求
第一版分兩個里程碑，兩個都是 Must：**v0.1** 先做最小循環（在線掛機、離線結算、存檔、上班模式、設定、設施、冒險），做完就開始自己玩；**v1.0** 補齊其餘能力，達成 M1（能走到第一次轉生）。之後的多人版另外規劃。Must 能力共 14 項（C01～C06、G01～G08）。

核心循環：設施產出的資源拿來養角色、做裝備；冒險掉落的材料拿來蓋設施或升級設施，兩邊互相供應。打倒區域 Boss 才能前往下一個區域。

## 5. 品質屬性需求
### 5.1 優先順序
衝突時排在前面的優先：

1. 易用性（含上班低調）：這是遊戲存在的理由
2. 可復原性：進度不見最傷
3. 可維護性：數值與內容會一直改，練遊戲設計要好改
4. 效能（含省資源）
5. 擴展性：為多人版預留
6. 可用性
7. 安全

可稽核性、可觀測性、成本：單人靜態網頁，不列品質需求。

### 5.3 屬性之間的取捨
| 衝突 | 取捨 |
|---|---|
| 易用性 vs 可維護性：偽裝畫面要像真的試算表，會多一套畫面要維護 | 易用性優先；偽裝畫面做成靜態樣板，不跟著遊戲內容變（ADR-0007） |
| 易用性 vs 可復原性：自動下載備份最安全，但上班時會被看到 | 易用性優先；改成 3 天一次不顯眼的提醒（QS-012） |
| 易用性 vs 效能：QS-001 要求隱藏 1 秒內生效，可是背景降頻可能延遲反應 | 隱藏鍵的處理不受降頻影響 |
| 擴展性 vs 可維護性：遊戲規則寫成純函式會多一點結構 | 接受；只做規則與畫面分開，不預先做多人存檔格式 |
| 效能 vs 可維護性：離線結算要用公式算，不能逐秒執行在線邏輯，兩邊可能算出不同結果 | 在線與離線用同一套「經過時間 → 收益」公式；中途發生升級、解鎖等事件時分段計算；任意切法結果差距在 1% 以內（SYS-007） |
| 可復原性 vs 易用性：在線與離線的界線（120 秒）太短，背景降頻時會誤判成離線；太長，睡眠一晚會拿到全額 | 120 秒：大於瀏覽器背景計時器最慢的約 1 分鐘，又遠小於一次睡眠 |
